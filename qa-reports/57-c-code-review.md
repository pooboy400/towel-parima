## ۴) رأی دربارهٔ طراحی «cancel-بی‌لاگ» (درخواست 57-a — فقط رأی، بدون تغییر)

**رأی: طراحی قابل‌قبول است (با یک بهبود اختیاری کم‌هزینه).**

- استدلال موافق: بدنهٔ >4KB از ابتدا «غیرسالم» فرض شده (گزارش مرورگر سالم چند صد بایت است)؛ لاگ‌کردن هر سرریز، کانال flooding جدیدی می‌ساخت (۳۰/min/IP × IPهای نامحدود). هر hit هنوز شمرده می‌شود (rate-limit قبل از خواندن) پس سهمیهٔ مهاجم محفوظ است؛ باند 2049..4096 بایت هم رکورد متادیتای `csp_violation_oversized` دارد → «سکوت» فقط برای بالای 4KB است که تهاجمی‌ترین باند است.
- استدلال مخالف (observability): بزرگ‌ترین حمله = کمترین ردپا؛ یک شمارنده/رکورد یک‌خطیِ `csp_body_capped` (بدون محتوا، با IP و حداقلِ «>4KB») دید حمله را برمی‌گرداند و چون هر IP سقف ۳۰/min دارد، سربارش کراندار است.
- **جمع‌بندی:** برای بستن فاز ۱ مانع نیست؛ پیشنهاد: رکورد متادیتای یک‌خطی در شاخهٔ capped (ترجیحاً throttled مثلاً یک‌بار در هر پنجرهٔ سقف برای هر IP) به‌عنوان آیتم کوچک فاز ۳ ثبت شود.
